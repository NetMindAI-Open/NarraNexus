## 2026-09-24 浏览器视觉输入

真实 Chrome 有头/无头：canvas 目标没有 DOM 句柄，只能从截图像素定位红色方块；视口观察与 selector
放大裁剪两种观察点击都必须命中，重复使用与滚动后的旧观察必须被拒绝，输出尺寸不超过封顶。
目标按「红色占主导」识别而不是精确色值：有头 Chrome 在 macOS 上按显示器色彩配置渲染，#e00000
会被截成约 (206,44,30)，无头则原样；精确阈值会让有头用例随显示器/窗口位置时过时不过。

2026-09-24：真实 Chrome 有头/无头验证人工新建、导航与标题更新、交还后 Agent 填写
新页面输入框、旁观关闭拒绝、owner 关闭活动页和最后一页、空白页再次导航。

## 2026-09-23 多页面支持

真实 Chrome 有头/无头覆盖 target=_blank、window.open、页面自主关闭、多页并存出帧、
后台页变化持续推送、动态标题/SPA URL、Agent 切换/新开/关闭以及末页补建。独立临时
profile 和本地 fixture，不触碰运行中的用户浏览器。首帧快照不能替代后台动态帧断言。
静态后台页 resize 后必须收到新尺寸的 metadata 和对应像素尺寸的 JPEG；仅检查
innerWidth/innerHeight 不能证明画面已更新。并发启动流与 resize 也不能覆盖新视口。

# 真实浏览器集成测试

正式 Chrome 无头回归覆盖空默认及历史 ask/deny、单站禁用、turn/thread 拒绝数据。
两个不同 origin 和不同会话下，导航、读取、填写和截图均成功，高级脚本依然拒绝。
网址审批回调已从启动接口删除。临时 profile 与本地页面不触碰用户正在登录的会话。

同一组真实帧、人工输入及持久 HttpOnly 登录测试分别使用托管 Chromium 与本机正式
Chrome。每次使用临时目录，系统 Chrome 缺失时明确跳过，不安装它，也不使用个人
profile。验证来源选择可继续内嵌显示，不把本地测试表单通过等同于知乎短信登录成功。

2026-09-23：两个来源均增加有头/无头矩阵，检查原生 UA 与实际模式一致，验证有头
浏览器同样支持画面流与接管。登录测试在关闭后切换到相反模式，使用同一个临时
profile 验证 HttpOnly 登录态保留，为网站兼容性对照提供底层证据。有头测试会打开
临时窗口；正常结束时关闭，用户正在使用的 profile 不受影响。

显式环境变量 NARRANEXUS_RUN_BROWSER_E2E=1 启用，不自动安装浏览器。
临时本地 HTTP 页面和临时 profile 避免依赖公网、用户登录态或站点 DOM。
验证两种模式出帧、排他接管、Agent 排队、中文粘贴、滚动、截图以及关闭后的
进程回收与重新启动后的 cookie 持久化。这些行为不能由 FakeCdp 单元测试证明。

登录用例不授予脚本权限。通过接管后的文本、Tab 和 Enter 提交
测试表单，由服务器设置 HttpOnly cookie；重启 Chromium 后服务器仍识别登录状态。
它验证的是浏览器登录机制与 profile 生命周期，不代表任何第三方网站的验证码或风控可自动通过。
审计不得包含输入的测试密码。

增加正常 BrowserService 读取持久模式的真实用例，无诊断入口或启动替身。通过保存
正式 Chrome 来源和有头模式启动，检查原生 UA；保存无头不替换当前会话，正常关闭
重开后变为无头且 Cookie 保留。该测试使用临时配置与 profile，不碰用户的运行实例。
