# scrollStickiness — 新消息能不能抢走滚动位置

## 为什么存在

team room 此前在消息数变化时**无条件** `scrollIntoView`。在一个六个 agent 可能同时回话的房间里，
这意味着**一个上翻去读两分钟前内容的用户，每隔几秒就被拽回底部**——房间在最忙的时候最不可读。

私聊早就有这条规则（只在视口已接近底部时跟随），但它写在一个 JSX 事件处理器里，
team 想用只能抄一份。**这条分支已经发现两份哈希调色板悄悄分了岔**，抽出来比以后再发现便宜。

## 阈值原样搬运

100px（贴底）和 50px（触顶加载）都是私聊的数字。它们不是从任何东西推导出来的，
**它们就是产品现在的手感**，在这里改会让两个界面莫名其妙地不一样。

## 两个默认值方向相反，是故意的

- `isNearBottom(null)` → **true**：首帧之前没有视口可量，默认「不跟随」会让房间打开时停在历史顶部。
- `isNearTop(null)` → **false**：这个判定会**触发一次拉取**，默认 true 会在 transcript 还没渲染时就发历史请求。
