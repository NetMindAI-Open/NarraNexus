# TeamBulletinPanel — 团队公告栏面板

## 为什么存在

在此之前，给团队下一条常驻指令只有一条路：在群里说。而群消息约 20 条之后就滑出所有成员的
视野，对后加入的人则从来不存在。用户的唯一补救是**重复自己**，而重复本身又吃掉了
让重复变得必要的那个窗口。

## 受控 + 纯展示

数据和重载由父组件持有，理由和 [[TeamWorkspacePanel]] 相同：公告栏变更会在 transcript 里
落一条系统行，所以 transcript 和面板必须对「什么时候变了」有共识，而这只能由一个组件持有。

## 预算是「展示」出来的，不是撞出来的

服务端对超长规则是**拒绝而非截断**，这只有在上限先出现在屏幕上时才算体贴——
否则用户写完一条才被告知不行。输入框旁边一个计数器成本为零，
却把一次拒绝变成了非事件。满了就直接禁用输入框。

服务端的拒绝**原样显示**（那句话点明了上限和数字），并且**保留草稿**，
这样用户可以直接改短重试。

## 署名是 agent 写权限的安全阀

agent 能钉规则；用户能删掉其中任何一条。这个制衡要真实成立，
前提是用户能一眼看出**哪些规则不是自己写的**——所以 agent 写的条目带可见标签，
没有标签的就是用户自己的。删除按钮**常驻挂载而非 hover 才出现**：
键盘用户无法 hover，而删除正是让 agent 写权限变安全的那个控件。

## 自动总结另起一节，视觉更轻

它是尽力而为的机器产出，紧挨着人手打的指令。**呈现得一模一样，就会读得一样权威。**
它也不计入条目数、不出现在规则列表里（所以只有总结、没有规则时，空状态照样显示）。

## 「清空」只按 tier

没有 clear-all。常驻规则正是用户最不想重打的部分，而不必重打就是这个功能存在的全部理由。
